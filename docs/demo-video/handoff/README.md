# CSight 1분 시연 영상 — Codex 녹화·편집 인계서

작성: 2026-09-20. 이 폴더 전체를 촬영 담당자에게 전달하세요.
목표: 실제 CSight 화면을 사용해 문의 확인 → 사람 판단 → 결과 기록 → 데이터 자산 흐름을 55~65초 영상으로 만든다.
기본 결과물: 1920×1080, 30fps, H.264 MP4, 한국어 자막. 음성·음악 없이도 이해되게 구성한다.

## 1. 받는 사람이 할 일 — 여기부터

1. 이 폴더를 압축 해제하고 Codex의 로컬 작업 폴더로 연다. 프로젝트 소스 전체는 필수가 아니다.
2. 아래 준비표에 담당자가 준 주소·시연 문의·저장 폴더를 채운다. 비밀번호는 문서나 채팅에 쓰지 않는다.
3. Plugins에서 **Chrome**과 **Computer Use**를 찾아 설치/활성화한다. 처음 뜨는 OS 권한은 직접 허용한다.
4. Chrome에서 시연 사이트에 로그인한다. 다른 개인 탭·알림이 녹화되지 않게 전용 창을 준비한다.
5. 새 Codex 작업에 `START_PROMPT.md`의 프롬프트 전체를 붙인다. Codex가 준비를 확인하면 녹화한다.
6. 최종 결정 확인창이 나오면 촬영 담당자가 내용을 읽고 직접 확정한다. 이후 편집은 Codex가 이어간다.

**‘딸깍’의 범위:** 환경 점검·장면 이동·컷 편집·자막·출력 검증은 자동화를 목표로 한다. 최초 권한·로그인·사람 최종 확정, 지원되지 않는 녹화 UI의 시작/종료까지 무조건 자동이라는 뜻은 아니다. 설치 가능한 기능은 계정·OS·앱 버전에 따라 현장에서 확인한다.

### 전달자가 채울 준비표

| 항목 | 입력/기본값 |
|---|---|
| 실제 접속 URL | 담당자가 제공. 빈칸이면 Codex가 한 번 질문 |
| 작업 OS | macOS 권장. Windows는 아래 대체 경로 |
| 계정 | 시연 전용 계정으로 사람이 로그인. 관리자 권한이면 데이터 자산 메뉴도 접근 가능 |
| 문의 | 최종 확정 전이고 사진·요약·정책 근거가 준비된 시연 문의 1건 |
| 문의 식별자 또는 직접 링크 | 담당자가 제공. 문의 제목만으로 동명이건을 추측하지 않기 |
| 선택할 결정과 사유 | 전달자가 실제 근거를 확인해 제공. 촬영용으로 무조건 허용하지 않기 |
| 재촬영 예비 문의 | 필요하면 동일 조건의 별도 시연 문의를 전달자가 준비 |
| 녹화 저장 위치 | 이 폴더 아래 `raw/` |
| 편집 저장 위치 | 이 폴더 아래 `output/` |
| 음성 | 기본 없음. 제공된 narration.wav가 있을 때만 사용 |

다른 컴퓨터의 `http://127.0.0.1:8080`은 **그 컴퓨터 자신의 서버**다. 원래 개발자의 화면에 있던 주소를 그대로 복사해서는 접속되지 않는다. 전달자가 승인된 시연 URL 또는 이미 설정된 원격 접속 경로를 제공해야 한다. 촬영자가 임의로 DB/GPU/서버를 설치하거나 공개하지 않는다. 원래 개발용 Mac에서 기동이 필요한 경우에만 프로젝트 담당자가 `scripts/csight_server_control.sh start`를 사용한다.

## 2. 도구 구성 — MCP를 여러 개 붙일 필요 없음

| 역할 | 권장 도구 | 설정/성공 판정 |
|---|---|---|
| 실행·파일 생성 | Codex 로컬 작업 + 기본 터미널 도구 | Python/FFmpeg 실행과 로컬 파일 쓰기 가능 |
| 브라우저 조작 | 공식 Chrome 플러그인 | 연결 안내를 마친 뒤 현재 CSight 탭의 제목과 버튼을 읽을 수 있음 |
| 앱·녹화 UI 조작 | 공식 Computer Use 플러그인 | Chrome과 녹화 앱을 읽고 조작할 수 있음 |
| 녹화 | macOS 스크린샷 도구 또는 FFmpeg AVFoundation | 5초 시험 녹화가 움직이는 영상 파일로 저장됨 |
| 편집·인코딩 | FFmpeg + ffprobe | 명령 실행, libx264 인코더, subtitles 필터 확인 |
| 자막 | 동봉 `captions.srt` | UTF-8, 한글 글꼴 정상 표시 |

기본 구성에는 별도 MCP JSON/TOML 파일이 없다. 플러그인이 제공하는 MCP는 설치 화면으로 연결한다. 같은 Computer Use 서버를 수동으로 또 등록하지 않는다. 일반 MCP의 사용자 설정 경로는 `~/.codex/config.toml`, 프로젝트 설정은 `.codex/config.toml`이지만 **이번 작업에는 직접 수정할 이유가 없다**. [공식 MCP 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

플러그인은 Plugins에서 검색→설치→필요한 연결을 완료한 뒤 새 작업에서 사용한다. Chrome/Computer Use는 공식 목록에 안내되어 있다. 이름이 안 보이면 가짜 서버 주소나 비공식 설치 명령을 만들지 말고, 현재 앱의 플러그인 가용성을 확인한다. [공식 플러그인 문서](https://learn.chatgpt.com/docs/plugins)

Computer Use 설정에서 서버/스킬을 활성화하고 필요한 앱 접근을 확인한다. macOS가 요청하는 화면 기록·손쉬운 사용 권한은 사용자가 직접 허용한다. 이미 허용됐으면 다시 요청하지 않는다. 현재 버전에 따라 Codex 앱 또는 ChatGPT 데스크톱의 Codex 작업에서 설정할 수 있으므로 설치된 앱 UI를 기준으로 한다. [공식 Computer Use 문서](https://learn.chatgpt.com/docs/computer-use)

**설치하지 않아도 되는 것:** Figma, Canva, Runway, 별도 FFmpeg MCP, DB MCP, GPU MCP. 생성 영상으로 제품 화면을 재현하지 않는다. 이 인계 작업을 위해 새 유료 계정이나 API 키는 기본적으로 필요 없다(기존 Codex 이용 환경은 필요).

### Codex 사전 점검 명령

```sh
python3 --version
ffmpeg -version
ffprobe -version
ffmpeg -hide_banner -encoders
ffmpeg -hide_banner -filters
```

`libx264`, `subtitles`를 실제 출력에서 확인한다. FFmpeg가 없으면 공식 다운로드 경로로 설치를 안내한다. 설치되어 있는 Homebrew를 사용하는 Mac은 사용자 승인에 따라 `brew install ffmpeg`로 설치할 수 있다. Homebrew 자체나 OS 권한을 몰래 설치/변경하지 않는다. [FFmpeg 다운로드](https://ffmpeg.org/download.html)

`subtitles` 필터가 없다면 libass가 포함된 배포판을 준비하거나, Codex가 한국어 자막을 투명 PNG로 렌더해 overlay하는 대체 편집 스크립트를 작성한다. 글꼴 이름은 설치된 한글 글꼴을 조사해 결정하고 5초 샘플에서 깨짐 여부를 확인한다.

## 3. 시나리오 — 최종 길이 60초

| 최종 시간 | 장면 | 실제 조작 | 자막 핵심 |
|---|---|---|---|
| 0–8초 | 문의 목록 | 준비한 문의를 선택 | 접수된 문의를 확인합니다 |
| 8–23초 | 사진·요약 | 사진을 보여주고 문의 요약에 시선 유도 | 사진과 요약으로 상황을 한눈에 |
| 23–33초 | 정책 근거 | ‘정책 근거·분석 상세 보기’를 열고 근거 확인 | 필요할 때 정책 근거 확인 |
| 33–45초 | 사람 판단 | 허용/비허용 선택, 확인창 검토, 사람이 확정 | 최종 판단은 담당자가 확정 |
| 45–52초 | 처리 결과 | 생성된 보고서의 결정·사유 확인 | 판단과 근거를 기록으로 보관 |
| 52–60초 | 데이터 자산 | 메뉴 이동, ‘쌓인 처리 기록’과 실제 운영 대상 구분 표시 | 처리 경험이 우리 팀의 자산으로 |

- 로그인, 입력 준비, 모델 분석 대기는 본편에서 제외한다. 분석 완료된 문의를 사용한다.
- 데이터 자산 메뉴가 없는 역할이면 촬영 전에 전달자가 적절한 시연 계정을 제공한다. 영상 중 계정 전환은 피한다.
- 처리 보고서는 생성 완료를 확인하고 촬영한다. 생성 지연은 원본에 남겨도 편집에서 제거할 수 있다.
- 실제 원본은 2~4분이어도 괜찮다. 에이전트 응답 대기시간까지 실시간 60초에 맞추려 하지 않는다.
- 각 장면은 움직임 종료 후 2~3초 정지해서 편집할 여유를 둔다. 마우스를 빠르게 휘젓지 않는다.
- 보고서 링크/최종 버튼 이름은 현재 화면에서 읽는다. 과거 문서의 좌표를 그대로 클릭하지 않는다.

### 시연에서 틀리게 말하면 안 되는 부분

- threshold 70%는 현재 UI의 빠른 검토 준비 기준이다. 결함 확률·모델 정확도70%라고 설명하지 않는다.
- 실제 환불·고객 발송이 아니라 모의 실행이다. 이를 표시하는 작은 자막을 유지한다.
- 최종 확정은 기록을 남기는 실제 변경이다. 리허설은 확인창에서 취소하고, 본 촬영 때 사람이 한 번 확정한다. 재촬영을 위해 DB를 초기화하거나 기존 결정을 되돌리지 않는다.
- 시연·미확인 기록은 ‘쌓인 처리 기록’에 포함될 수 있지만 ‘실제 운영 분석에 쓸 수 있는 기록’ 및 최근 실운영 사례와 다르다. 건수 증가를 확인하지 못했으면 ‘방금 1건 늘었다’는 자막을 쓰지 않는다.
- 자산 화면의 0건을 감추기 위해 HTML/응답/DB를 변조하지 않는다. 현재 시스템이 자동으로 학습해 성능이 향상됐다고 말하지 않는다.
- 완전한 합성 fixture로 찍게 되면 먼저 촬영 방식 변경을 사용자에게 알리고 ‘UI 동작 예시’라고 명시한다. 실제 업무 녹화처럼 납품하지 않는다.

## 4. 녹화 절차

### 기본 경로: Mac의 화면 기록 + Codex 화면 조작

1. 시연용 Chrome 창을 하나만 준비한다. 가능하면 16:9 화면/영역으로 녹화한다. 주소창·개인 북마크는 제외한다.
2. `Shift–Command–5`에서 선택 영역 기록을 고른다. `raw/`에 저장한다. 마이크는 기본 끈다.
3. 먼저 5초 시험 녹화한다. 저장된 파일에서 CSight가 움직이고 글자가 읽히는지 확인한다.
4. 본 녹화 시작 후 Codex가 장면을 순서대로 진행한다. 화면 조작은 설치된 브라우저/Computer Use 도구의 문서대로 한다.
5. 사람 최종 확정이 필요한 지점에서 잠시 인계한다. 확정 후 Codex가 보고서와 데이터 자산으로 이동한다.
6. 녹화를 멈추고 실제 파일 경로를 Codex에 알려준다. 새 파일의 생성·길이를 확인한다.

화면 기록은 별도 녹화 도구의 역할이다. Computer Use의 스크린샷 기능을 60초 MP4 녹화 기능으로 오해하지 않는다. 녹화 UI를 Codex가 조작할 수 없으면 사용자가 시작·종료 두 번만 한다. [Apple 화면 녹화 안내](https://support.apple.com/en-us/102618)

### 선택 경로: FFmpeg로 녹화 자동화

Codex 터미널에서 캡처가 허용되고 화면 기록 권한을 받은 경우에만 사용한다. 지원되지 않으면 위 기본 경로로 바로 전환한다.

```sh
ffmpeg -f avfoundation -list_devices true -i ""
```

출력에서 **Capture screen** 장치의 번호를 확인한다. 카메라 번호를 선택하지 않는다. 아래 `SCREEN_INDEX`는 실제 확인한 숫자로 대체한다.

```sh
ffmpeg -n -f avfoundation -framerate 30 -capture_cursor 1 \
  -i "SCREEN_INDEX:none" -t 240 -an \
  -c:v libx264 -preset ultrafast -crf 18 -pix_fmt yuv420p raw/take-01.mp4
```

장치 열거는 입력이 없어서 종료 코드가 비정상이어도 목록은 나올 수 있다. 반면 본 녹화 실패는 숨기지 않는다. PTY/비동기 세션으로 실행해 UI 조작과 병행하고, 종료는 해당 세션에 `q`를 보내 정상 마무리한다. 다른 FFmpeg 작업을 일괄 종료하지 않는다. 본 녹화 전에 5초 파일을 검사한다. [FFmpeg AVFoundation 장치 문서](https://ffmpeg.org/ffmpeg-devices.html#avfoundation)

Windows에서는 설치된 녹화 앱/OS 녹화 기능으로 동일한 raw 영상을 확보한다. Mac 명령을 그대로 실행하지 않는다. Chrome/Computer Use가 지원되지 않는 환경이면 사람이 장면을 따라 녹화하고 Codex가 편집만 진행한다. 이 대체 경로도 최종 산출물 규격은 같다.

## 5. 편집 — Codex가 수행할 작업

1. `ffprobe`로 원본의 길이·해상도·프레임레이트·오디오 유무를 확인한다.
2. 장면 전환 근처의 프레임을 추출해 실제 내용으로 컷 지점을 정한다. OCR/화면 읽기 없이 시간을 추측하지 않는다.
3. 동봉 `edit-plan.json`의 `source_in/source_out`을 원본의 실제 초 단위로 채운다. 현재 null은 미촬영을 뜻한다. `duration`은 최종 목표 길이다.
4. 불필요한 대기·실수·로그인·Codex 화면을 제거하고 장면별 파일로 정리한다. 속도는 가급적1배, 이동만 최대1.5배. 장면이 짧으면 읽을 수 있는 정지 화면을 늘려 맞춘다. 최종 확정 내용을 읽는 구간은 빠르게 돌리지 않는다.
5. 1920×1080/30fps로 통일한다. 화면이16:9가 아니면 중요한 UI를 자르지 말고 여백으로 맞춘다. 원본이 작으면 해상도 확대만으로 글자가 선명해지지 않으므로 재촬영을 우선 검토한다.
6. 하단 자막용 공간을 확보한다. 버튼·문의 요약·최종 확인문을 자막으로 덮지 않는다. 필요하면 화면을 약간 축소해 하단 띠를 확보한다.
7. `captions.srt`를 실제 편집 타임라인에 맞춘다. 한글 글꼴로 번인한다. 모든 장면에 ‘시연 데이터 · 외부 조치는 모의 실행’ 표시를 작게 유지한다.
8. 기본은 무음. 음성을 요청하면 동봉 문구를 읽은 실제 녹음 파일을 받거나 사용자가 승인한 TTS를 사용한다. 몰래 유료 API를 사용하지 않는다. TTS 사용 시 AI 음성임을 납품 메모에 적는다.
9. `final.mp4`, 자막 없는 `clean.mp4`, `captions.srt`, 채워진 `edit-plan.json`, 실행한 `render.py` 또는 셸 스크립트, `QA.md`를 출력한다. 원본은 유지한다.

FFmpeg의 `trim/setpts`, `scale/pad`, `concat`, `subtitles` 등으로 구현할 수 있다. 설치된 필터를 확인한 후 코드를 만든다. 파일 경로는 Python subprocess의 인자 배열로 전달해 공백·한글·따옴표 문제를 피한다. 입력을 덮어쓰지 않는다. [FFmpeg 필터 문서](https://ffmpeg.org/ffmpeg-filters.html)

## 6. 납품 전 검사 — ‘명령 성공’으로 끝내지 않기

- 길이55~65초, 1920×1080, 30fps, H.264/yuv420p MP4인지 ffprobe로 확인한다.
- 6개 장면이 순서대로 존재하고 클릭 결과·보고서가 실제 화면과 일치하는지 확인한다.
- 각 컷 경계 전후와 자막 구간마다 프레임을 확인한다. 한글 깨짐·검은 화면·개인정보 노출·잘린 사진이 없어야 한다.
- final.mp4를 처음부터 끝까지 재생한다. 음성이 있으면 잘림·크기·자막 싱크를 듣고 확인한다.
- ‘판단은 담당자’, ‘모의 실행’, ‘전체와 실운영 기록 구분’이 정확한지 확인한다.
- 원본 시연 계정 비밀번호, 세션 토큰, 고객 개인정보는 녹화/납품에 포함하지 않는다.
- QA.md에 실제 실행한 항목만 PASS로 표시한다. 미확인 항목은 NOT_RUN과 이유를 적는다.
- 파일 생성만으로 완료라고 말하지 않는다. 출력 파일 링크와 검사 결과를 함께 전달한다.

## 7. 이 패키지의 현재 검증 상태

이 패키지는 촬영 인계 문서·실행 프롬프트·자막·편집 계획이다. **실제 원본 영상과 완성 영상은 아직 없다.**
문서 링크 및 SRT/JSON 형식은 작성 환경에서 점검한다. 다른 사람의 OS 권한, 플러그인 연결, 서버 접근, FFmpeg 캡처와 실제 편집은 그 사람의 환경에서 5초 시험으로 확인해야 한다.
이 문서는 플러그인 자체가 아니며 설치 파일도 아니다. 커스텀 MCP 서버 없이 공식 플러그인과 로컬 도구를 사용하도록 설계했다.
