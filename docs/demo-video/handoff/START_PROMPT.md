# 새 Codex 로컬 작업에 아래 내용을 그대로 붙여 넣으세요

이 폴더의 README.md, edit-plan.json, captions.srt를 읽고 CSight 시연 영상의 녹화부터 편집·검증·파일 납품까지 진행해 줘. 설명이나 계획만 제시하고 끝내지 말고 실제 가능한 작업을 실행해 줘.

목표는 실제 서비스 화면으로 만든 55~65초의 한국어 제품 시연 영상이야. 문의 확인 → 사진·요약 → 정책 근거 → 사람이 최종 판단 → 처리 보고서 → 데이터 자산 순서로, 기능 나열보다 실무자의 업무 흐름이 보여야 해. 기본 출력은 1920×1080, 30fps, H.264 MP4, 자막 포함, 무음이야. 유료 영상 서비스나 API는 사용하지 마.

먼저 내가 채운 README 준비표와 현재 컴퓨터에서 가능한 도구를 확인해 줘. 기존 Chrome/Computer Use 플러그인을 우선 사용하고, 현재 제공된 도구 이름과 문서를 읽어. 플러그인 도구 이름이나 영상 녹화 API를 지어내지 마. 별도 MCP 서버는 기본적으로 필요 없어. FFmpeg와 ffprobe는 로컬 터미널로 사용해. 원본 녹화는 Mac 화면 기록 도구 또는 사용 가능한 FFmpeg 캡처로 수행해. 화면 조작은 설치된 브라우저/Computer Use 도구의 정책을 따라.

URL이나 대상 문의가 없으면 필요한 값만 묶어서 한 번 질문해 줘. localhost를 다른 사람 서버라고 가정하지 마. 로그인·OS 권한은 내가 직접 처리하고, 이미 처리된 권한은 다시 묻지 마. 네가 직접 해결할 수 있는 폴더 생성·도구 점검·로컬 편집·재검증은 계속 진행해. 기존 서비스 코드, 데이터베이스, 모델 설정, 문의 결정 이력을 수정/초기화하지 마.

실제 촬영 전에 5초 시험 영상을 저장해 화면·파일·해상도가 정상인지 검사해 줘. 브라우저 창을 실제 녹화하는 화면에 보이게 배치하고, Codex 채팅이나 비밀번호가 찍히지 않도록 해. 그다음 본 촬영을 시작해. 원본이 2~4분이어도 괜찮아. 장면마다 잠시 멈춰 편집할 여유를 확보해.

리허설에서는 최종 확정하지 마. 본 촬영에서도 최종 판단 버튼은 내가 직접 확인하고 확정할게. 확인창이 준비되면 내가 할 한 가지 행동만 짧게 알려주고 기다려. 내가 완료했다고 하면 화면에서 결과를 확인한 다음 보고서와 데이터 자산 장면을 계속 촬영해. 나머지 단순 이동과 접기/펼치기는 직접 해 줘.

사진과 요약, 정책 근거는 실제 제공된 화면을 사용해. 완료/성능/건수를 가짜 HTML, 응답, 자막으로 꾸미지 마. threshold 70%를 정확도라고 표현하지 마. 데이터 자산의 전체 기록과 실운영 분석 대상 건수를 구분해. 최근 사례가 비어 있으면 빈 상태를 사실대로 보여주고, 기존 기록으로 채우려고 서버를 바꾸지 마. 최종 영상에는 ‘시연 데이터 · 외부 조치는 모의 실행’을 작게 표시해.

녹화 도구가 지원되지 않거나 OS가 녹화를 막으면 내가 시작/종료만 하도록 정확한 방법을 알려줘. 더 이상 화면 조작이 불가능하면 README의 장면표대로 내가 녹화하고 raw 파일을 넘기는 대체 경로로 전환해. 장애를 숨기거나 스크린샷 슬라이드를 실제 화면 녹화라고 납품하지 마.

원본이 확보되면 프레임을 읽어 실제 컷 지점을 찾고 edit-plan.json의 null을 채워. 자막 타이밍을 맞추고 FFmpeg로 컷 편집·정규화·자막 삽입을 실행해. 한국어 글꼴을 검사하고, 사진/버튼/확인 문장을 덮지 않도록 자막 위치를 조절해. 원본 오디오는 기본 제거하고 음악은 넣지 마. 제공된 음성 파일이 있을 때만 싱크를 맞춰 넣어.

최종 파일을 실제 재생하고 컷 경계·자막 깨짐·길이·해상도·프레임레이트를 확인해. output/final.mp4, output/clean.mp4, output/captions.srt, 완성한 edit-plan.json, 실제 실행한 재현 가능한 편집 스크립트, output/QA.md를 만들어 줘. 원본은 삭제하지 마. QA에는 실제 확인한 것만 PASS로 적고 불가능했던 검증은 NOT_RUN이라고 적어 줘. 최종 답변은 파일 링크와 실제 완료/미완료만 간단히 정리해 줘.
